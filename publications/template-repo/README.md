# Cognitive Asset Package Template

This is a draft GitHub template repository for creating a Cognitive Asset Package.

A Cognitive Asset Package is a structured folder or repository for preserving the context, judgment, constraints, decisions, and AI collaboration protocols behind long-term human-AI work.

It is not a normal project folder. It is not a prompt library. It is not a raw chat export. It is a portable restoration layer for human-AI cognition.

## Relationship to the Whitepaper

This template implements the Cognitive Asset Package concepts introduced in the whitepaper *Cognitive Assets: The Emergence of Persistent Human-AI Cognition*.

The canonical structure originates from the whitepaper's Minimum Cognitive Asset Package (MCAP). This repository is a practical starting point for implementing that structure in Markdown. It is not a finalized industry standard.

Start private by default. A Cognitive Asset Package may contain project context, decision reasoning, rejected paths, or collaboration protocols that should not be published without review.

## Who this is for

This template is for people or teams who use AI systems in work that requires continuity, accountability, or careful judgment.

It may be useful for:

- researchers
- writers and editors
- software developers
- designers
- founders
- policy teams
- educators
- independent knowledge workers
- organizations using AI-assisted decision support

## How to use this template

1. Copy this template into a new repository or project folder.
2. Start with the canonical MCAP files: `project-context.md`, `glossary.md`, `decision-log.md`, `judgment-rules.md`, `failure-record.md`, `workflow-map.md`, `source-and-evidence.md`, and `review-status.md`.
3. Use `STRUCTURE.md` to understand how canonical files, support files, and publication-facing files relate.
4. Fill in `profile.md` only with safe owner, domain, and collaboration preferences.
5. Use `judgment-principles.md` and `decision-history.md` as support or companion files when useful.
6. Define how AI should assist in `ai-collaboration-protocol.md`.
7. Use `export-checklist.md` before moving the package into another AI system, repository, or public archive.
8. Review the package periodically and mark outdated material clearly.

## Privacy Warning

Do not include unnecessary personally identifiable information.

Do not include credentials, passwords, API keys, access tokens, private keys, or security secrets.

Do not include confidential client data, private communications, sensitive organizational details, or unpublished third-party material unless you have permission and a clear reason to preserve it.

Review, redact, and anonymize the package before publication.

## What not to put inside

Do not place unnecessary sensitive information in this package.

Avoid including:

- private personal data not required for restoration
- passwords, API keys, or credentials
- confidential material without permission
- raw chat logs containing irrelevant or sensitive content
- unverified claims presented as facts
- copyrighted material without rights or citation
- instructions that delegate final human responsibility to AI

If sensitive material is necessary, summarize or anonymize it whenever possible.

## Why it matters

AI collaboration can produce useful outputs quickly, but outputs alone do not preserve the judgment that shaped them.

A prompt may preserve an instruction. A file may preserve a result. A chat log may preserve a sequence. But serious work also depends on context, constraints, rejected paths, decision reasons, and authority boundaries.

This template helps preserve those elements so that human-AI collaboration can be resumed, reviewed, and transferred across time.

The goal is not to automate judgment. The goal is to keep judgment visible.
